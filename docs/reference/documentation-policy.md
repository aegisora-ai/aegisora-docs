# Documentation Policy

Aegisora documentation follows a source-of-truth model.

## Rules

1. Documentation describes released or explicitly planned behavior.
2. Security claims require evidence, implementation references, or clearly stated assumptions.
3. Integration documentation should identify tested versions where relevant.
4. Public APIs must be distinguished from internal implementation details.
5. Breaking changes should be documented with the corresponding release.

The documentation repository is a public developer surface and should remain understandable without access to internal project discussions.
